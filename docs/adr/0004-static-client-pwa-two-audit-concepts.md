# v1 is a fully static client-side PWA; two distinct audit concepts replace "the app needs a backend for audit"

We considered a backend for governance/audit purposes, but rejected it for v1: there is no patient database and no server-side patient/session logging, since Case State is transient input, not a persisted record (see [ADR-0002](./0002-no-patient-record-subsystem-in-v1.md)). The stack is Vite + React + TypeScript, mobile-first responsive, PWA-ready, with no application backend.

Static does not mean no audit trail — it means no *server-side patient/session* audit log. Two separate concepts exist:

- **Decision Execution Trace**: generated by the deterministic engine for one evaluation (Case State inputs, Active Rule-Set Release version, matched rules, Recommendation Set, Rationales, Provenance, engine/schema version). Ephemeral unless the user explicitly exports it.
- **Clinical Knowledge Governance Audit**: how the *knowledge base itself* changed over time — git history, GitHub Issues/PRs/reviews, ADRs, immutable Rule-Set Releases, Release Manifests, and clinical fixture/test history. This exists independently of any running application backend.
